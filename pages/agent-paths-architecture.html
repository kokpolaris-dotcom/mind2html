AGENT 研发解耦 · 方向校准与架构

精力应从「把 Mastra 封装进 Admin」转向文旅行业深水区

研发团队在自有仓库基于框架完整开发；平台收敛到统一接口与底座能力建设。

解耦原则

接口与规范由平台统一定义，实现与托管位置可替换；
研发能力不再绑定平台的封装进度。

Mastra / Runtime 能力
  • 底座大量精力花在把 Mastra 能力开放给 Admin，只为让 Agent 团队能在 Admin 上开发 —— 并非高价值工作
  • 精力实际多花在定制化内容上，纯粹的 Mastra 能力占比很少；Mastra 更像内部平台框架，缺少商业化所需核心组件，相当于「毛坯房」
  • 低代码平台与开发平台本是两个方向，硬要融合导致周期过长、非常别扭
双方共识 什么才是真正的价值
  • 真正的价值在文旅行业深水区：沙箱增强 · 记忆增强 · 上下文管理增强
  • 沙箱、记忆、响应速度等核心能力长期没人做，精力反被非核心的商业化组件占用
  • 这些深水区能力应被深度保护，作为底座重点投入
